# 規劃與決定

這份文件記錄所有已經討論定案的內容。日期：2026-11-17。

## 1. 前提

- 使用者**沒有 Mac**、**不簽署**（不用 AltStore 等側載），**不花錢**。
- 因此做成 **PWA**：放在 GitHub Pages，用 Safari「加入主畫面」。
- PWA 做不到的部分（小工具、背景定位、讀步數）用 iPhone 上的免費工具補：**捷徑**、**Scriptable**、**Overland 或 OwnTracks**（背景定位 App，做之前要確認仍可在 App Store 下載）。
- **不使用** Google 地圖時間軸匯入。

## 2. 核心概念

一筆「紀錄」＝ 金額（可空）＋ 日記（可空）＋ 地點（自動）＋ 照片（可多張）。

- 只有金額 → 單純記帳；只有文字 → 單純日記；兩者都有 → 花錢時順手寫心情。
- 日記分兩種：
  - **隨手記**：綁定當下時間和地點，排在時間軸上。
  - **每日總結**：不屬於任何時間點，固定顯示在當天最上面，可不寫。
- 旅程中每天的總結串起來就是遊記。

## 3. 畫面（預覽圖已畫）

1. **地圖首頁（單日）**：地圖為主，畫當天路線；記帳點顯示為 $，有照片的紀錄直接在地圖上顯示縮圖。下方可往上拉的面板：今日支出、地點數、公里數、時間軸。右下角 + 新增紀錄。底部分頁：地圖／日曆／旅程／統計。地圖和時間軸互相連動，可播放當天行程。
2. **一天的完整回顧**：上方縮小地圖，接著每日總結卡片（含心情），再來完整時間軸（含自動軌跡的「離開家」「抵達公司」等灰色小字、記帳、日記文字、照片）。
3. **新增紀錄**：支出／收入／只寫日記切換；大字金額＋幣別切換（顯示換算台幣與匯率）；分類圖示（餐飲、交通、購物、住宿、門票…）；日記文字框；照片；地點（自動定位）；時間。
4. **主畫面小工具**：Scriptable 中型（今日支出、本月預算進度、最後地點、路線縮圖）、Scriptable 小型（一年前的今天）、捷徑小型（快速記一筆）。
5. **旅程地圖**：選日期範圍建立旅程，每天一種顏色，統計總花費、公里數、照片數、紀錄數、每日花費長條，按鈕「生成旅遊軌跡圖」。
6. **旅遊軌跡圖（簡潔版）**：地名大標、日期與天數、路線圖、地點標籤、每日顏色圖例、公里／地點／照片／花費。可存相簿或分享。

尚未畫：日曆頁、統計頁。

## 5. 架構

```
iPhone 自動記錄                雲端（免費）             你看到的地方
健康 App → 捷徑 ───────────→ Supabase 資料庫 ←──→ 摳摳手帳 App（PWA）
Overland/OwnTracks ────────→ （紀錄、軌跡、步數）  ──→ Scriptable 小工具
                              Cloudflare R2 ←────── App 上傳照片
借用的免費服務：GitHub Pages（放 App）、OpenStreetMap（地圖、地名、店名搜尋）、匯率 API
```

- **手機為主、雲端同步**：資料先存手機（IndexedDB），沒網路也能用，有網路再同步。
- **Supabase**：資料庫＋登入；用 RLS 確保只有本人讀寫；也是捷徑、背景定位 App、Scriptable 的收件匣／資料來源；同時是備份。
- **Cloudflare R2**：存照片（免費 10 GB、下載不收流量費）。上傳需要一個小型伺服器端程式（Supabase Edge Function 或 Cloudflare Worker）代簽上傳網址，R2 金鑰不能放在 PWA 裡。
  - 第 2 階段實作：用 **Cloudflare Worker＋R2 綁定**直接收發照片（不用簽網址，也完全不需要 R2 金鑰）；Worker 向 Supabase 確認登入 token，照片存在 `<使用者 id>/<照片 id>/thumb|display`，只能存取自己的。
- **地圖**：Leaflet＋OpenStreetMap 圖磚。去過的區域暫存；出國前可預先下載旅遊地區。
- 軌跡點之間預設畫直線，可選擇用免費路線服務推算道路（標示為推測）。

## 6. 各功能怎麼做

| 功能 | 做法 | 依賴 |
|---|---|---|
| 地圖＋每日路線 | 軌跡點依時間連線畫在地圖上 | Leaflet、OSM |
| 生活軌跡 | 背景定位 App 持續記錄並自動上傳；捷徑每小時補一個點當備援；也可手動「打卡」 | Overland/OwnTracks、捷徑、Supabase |
| 軌跡精簡 | 30 天前的軌跡去掉多餘點（停留重複點、直線中間點），省 80～90% | 資料庫排程或 Edge Function |
| 步數 | 捷徑每天 23:55 用「尋找健康樣本」讀步數、步行距離，送到 Supabase；設為不需確認自動執行 | 捷徑、健康 App |
| 記帳 | 數字鍵盤、分類圖示；每日／每月／分類統計 | App |
| 日記 | 隨手記＋每日總結 | App |
| 照片 | 見第 7 節 | R2 |
| 自動附地點 | 存檔時抓 GPS，再查地名 | iPhone 定位、Nominatim |
| 多幣別 | 預設新台幣，每筆可切換；每筆存原幣金額、當時匯率、換算台幣；匯率每天抓一次可手動改；人在國外時自動建議當地幣別 | 免費匯率 API（要含 TWD） |
| 旅程 | 選日期範圍；每天一色；總花費、每日花費、公里數、步數、照片數 | App |
| 旅遊軌跡圖 | Canvas 繪製路線＋統計輸出圖片 | App |
| 主畫面小工具 | Scriptable 讀 Supabase 今日資料；點擊開 App | Scriptable |
| 快速記一筆 | 捷徑依序問金額、分類、一句話，附位置送出；可放主畫面、控制中心 | 捷徑 |
| 離線與備份 | 先存手機再同步；一鍵匯出全部資料（JSON＋照片），用通用格式，不綁死服務 | App |

- 第 3 階段實作（生活軌跡）：iOS 捷徑的「特定時間」自動化只有每天／每週／每月，**沒有每小時**，備援改成「幾個不同時間各一個自動化」（可不做）。時間軸不列出每個軌跡點，改成 150 公尺內待超過 10 分鐘＝停留，顯示「抵達／離開 ○○」。
- 第 3 階段實作（自動化的認證）：背景定位 App、捷徑、小工具不能用帳號密碼登入，改用 App 產生的「自動化金鑰」（Supabase 只存雜湊）。接收端掛在照片伺服器 Worker 的 `/auto/…`，Worker 帶金鑰呼叫 Supabase 的 `auto_*` 函式（security definer），不需要任何秘密金鑰。

## 7. 照片策略（已定案）

- PWA 無法連結相簿照片，選取時拿到的是複製檔，所以照片**以雲端為主**。
- 在手機上壓縮後上傳兩種尺寸：
  - **縮圖**：長邊 400px，約 25～30 KB，**手機和雲端各留一份**（地圖、時間軸、旅程頁用，離線可看）。
  - **顯示版**：長邊 2048px，約 375 KB（WebP）／530 KB（JPEG），**上傳成功後刪除手機上的副本**。
- 優先 WebP（Safari 可能無法輸出 WebP，需用 WASM 編碼器）；實測效果不好就退回 JPEG 畫質 80%。
- 大圖點開時才下載並暫存，暫存上限 200 MB（可調），超過刪最久沒看的。可「下載這趟旅程的照片」離線看。
- 原圖不上傳，留在 iPhone 相簿；App 記下拍攝時間方便找回。
- 出國時可設定「照片只在 Wi-Fi 上傳」。
  - 第 2 階段實作：iOS 的網頁 App 偵測不到目前是不是 Wi-Fi（Safari 不支援 Network Information API），改成手動開關「暫停照片上傳」。

## 8. 店名

1. **店名搜尋**（2026-11-17 使用者決定：**不要**自動列出附近店家）：店名欄打字後按搜尋，查附近約 30 公里內符合的店，近的排前面（Nominatim → Photon → Overpass），點選後紀錄地點改成店的位置；找不到就直接用輸入的店名。常常到家才補記，所以範圍要大、時間要好改。也可以打「地區＋店名」（例如「嘉義幸福」）在指定縣市／鄉鎮市區裡找。
2. **記住去過的店**：同地點記過的店排最上面，帶入上次的分類與常見金額。
3. **掃電子發票 QR Code**：解析賣方統編、金額、日期；統編查公司登記公開資料換店名，可改簡稱並記住。
4. ~~**軌跡提醒**（有背景定位後）：偵測在某處停留，主動詢問要不要記一筆。~~ → **不做**（使用者 2026-11-19 決定：忘了記帳算自己的，不需要提醒）。

不採用：Google Places（需綁信用卡）、Apple MapKit（需付費開發者帳號）。財政部載具 API 之後再研究能否申請。

## 9. 容量與用量估計（一般使用）

- 照片：每年約 1,400 張 × 375 KB ≈ 525 MB → R2 10 GB 約 19 年。
- 資料庫：軌跡（每天約 2,000 點，精簡後）約 25 MB／年＋紀錄 4 MB／年 → Supabase 500 MB 約 16 年。
- 整體約可用 15 年；風險在免費方案規則改變 → 靠匯出功能保留可搬家能力。
- 手機：第一年約 300～400 MB（含有上限的暫存），之後每年約 +65 MB。
- 行動網路流量：每月約 100～200 MB。
- 電量：每天約 4～6%（背景定位為主）。
- Supabase 一週無活動會暫停，但每天自動上傳會讓它保持活動。

## 10. 階段

1. **核心 App**：地圖首頁、時間軸、新增紀錄、照片壓縮（先存本地）、自動定位與地名、店名搜尋、記住去過的店、多幣別、IndexedDB、離線（Service Worker）、PWA 設定、GitHub Pages 發布、匯出備份。
2. **雲端**：Supabase 登入、資料表與 RLS、同步與離線佇列；R2 照片上傳（Edge Function／Worker 代簽）、縮圖／顯示版策略、大圖暫存。
3. **自動化**：背景定位接收入口、捷徑（快速記一筆、每晚步數、每小時定位）教學、Scriptable 小工具腳本、Supabase 讀取權限設定。
4. **進階**：旅程、旅遊軌跡圖、日曆、統計、軌跡精簡、掃發票、使用狀況頁（軌跡停留提醒已決定不做）（雲端空間、流量）。

## 11. 限制與注意

- 使用者要在真的 iPhone 上測試：加入主畫面、定位權限、捷徑、Scriptable、背景定位 App。開發時可用 Playwright 模擬手機畫面測試大部分功能。
- 捷徑無法直接產生安裝檔，要寫一步一步的教學給使用者建立。
- 帳號（Supabase、Cloudflare）由使用者自己註冊，不經手密碼。
- 一個階段開一次新的工作階段，以節省用量。
